# Release Notes Updater (`docs/release_notes.md`)

This skill automates gathering, categorizing, synthesizing, and documenting major changes, bug fixes, and deprecations in MaxText to announce in upcoming releases. It can be run either on a schedule or ad-hoc for any date range.

## Workflow Steps

### 1. Gather Commits & Pull Requests

Run the helper script [gather_changes.py](../update-changelog/scripts/gather_changes.py) from the repository root to extract commits since the last checked commit (`**Last Updated**: <commit_hash>` in `docs/release_notes.md`, or the last commit that touched `docs/release_notes.md`):

```bash
python3 .gemini/skills/update-changelog/scripts/gather_changes.py
```

The script automatically:
- Walks `--first-parent` on `main` and resolves GitHub Merge PR numbers (`#XXXX`) to their initial feature/fix commit on the PR branch (ignoring follow-up review feedback or comment cleanup commits).
- Excludes any changes in `tests/`, `.github/workflows/` (and `.github/`), `.gemini/`, `src/maxtext/training_engine/`, `src/maxtext/experimental/` (`experimental/`), `tools/dev/`, `src/dependencies/dockerfiles/`, `README.md`, and `docs/release_notes.md`.
- Excludes container/Docker image vulnerability fixes, Docker registry migrations (e.g., Artifact Registry), Gemini/agent skill updates, `pytest-split` / test runner splitting, `Latest News` announcements, `"No public description"` commits, and test-only fixes.
- Strips Copybara/Piper internal metadata (`PiperOrigin-RevId`).
- Reads `**Last Updated**: <commit_hash>` from `docs/release_notes.md` (if present) so subsequent runs automatically inspect only commits in `<last_commit>..HEAD`.
- Consolidates multi-part PR series (e.g., `[NNX] Delete Linen (1/5)..(5/5)`, `FP8`, `DeepSeek-V4`) into single unified entries.
- Categorizes commits into the three standard MaxText release note sections (`#### Changes`, `#### Bug Fixes`, and `#### Deprecations`).
- Filters out minor internal noise (review feedback commits, comment/description cleanups, linter fixes, reverts of typos).

### 2. Synthesize Major Release Announcements

Review the candidate list generated by the script and synthesize related commits into polished, user-facing bullet points under the three sections in `docs/release_notes.md`:
1. **`#### Changes`**:
   - **Group related PRs**: If multiple PRs contribute to a single feature (e.g., FP8 Orbax restoration and scale tensor ingestion), combine them into a single cohesive bullet with multiple PR links: `([PR #5051](...), [PR #5052](...))`.
   - **Use MaxText Category Headings**:
     - **Pre-Training** (models, decoders, MoE routing, attention, context parallelism, MTP, NNX migration)
     - **Post-Training** (GRPO, DPO, SFT, LoRA/QLoRA, Raiden weight sync, vLLM rollout)
     - **Performance** (FP8/FP4, Qwix, AQT, Muon optimizer, SparseCore, GEMM overlap)
     - **Usability** (Grain, wandb, evaluation harnesses, tutorials, configs)
     - **Checkpointing / Goodput** (Orbax, Zarr3, OCDBT, multi-tier checkpointing, elasticity)
2. **`#### Bug Fixes`**:
   - Group notable user-facing bug fixes by category (`Pre-Training`, `Post-Training`, `Performance`, `Usability`, `Checkpointing / Goodput`) with PR links.
3. **`#### Deprecations`**:
   - Merge all deprecations into a single unified list under `#### Deprecations` (without splitting into category subheadings). Document deprecated or removed configuration flags, legacy modules/layers (e.g., Flax Linen removal, `pure_nnx` config flags), deprecated CLI scripts, or dropped dependencies.

*Note*: Always exclude changes in `tests/`, `.github/workflows/`, `src/maxtext/training_engine/`, `src/maxtext/experimental/` (`experimental/`), `tools/dev/`, `.gemini/`, `README.md`, container/Docker image vulnerability fixes, Docker registry migrations, `pytest-split` CI changes, `Latest News` announcements, `"No public description"` commits, and review-feedback/lint cleanups.

### 3. Update `docs/release_notes.md`

1. Open [docs/release_notes.md](../../../docs/release_notes.md).
2. Update `**Last Updated**: <head_commit_hash>` under `## Unreleased` and insert the newly synthesized items below `<!-- Add new unreleased changes below this line -->` under `#### Changes`, `#### Bug Fixes`, and `#### Deprecations`.
3. Preserve all existing `Unreleased` and historical release entries. Do not create a root `CHANGELOG.md`.

### 4. Validation

Verify your changes before completing the task:
1. Run `git diff docs/release_notes.md` to ensure clean Markdown formatting and that `**Last Updated**: <head_commit_hash>` is updated.
2. Confirm that every PR link follows the format `[PR #XXXX](https://github.com/AI-Hypercomputer/maxtext/pull/XXXX)`.
3. Re-run `gather_changes.py` to verify that it detects `**Last Updated**: <head_commit_hash>` and reports `No new commits`.
